## 📊 금융 API 조사 보고서: 토스 증권 API 접근 전략 (Research Plan)

### 🎯 1. 조사 목표 및 범위 설정 (Scope Definition)

우리가 조사해야 할 API는 단순히 "데이터를 가져오는" 기능이 아니라, **"비즈니스 로직을 구현하는"** 도구여야 합니다. 따라서 조사 범위는 다음 3가지 핵심 영역에 초점을 맞춰야 합니다.

| 조사 영역 | 목표 데이터 | 필요한 조사 내용 | 중요도 |
| :--- | :--- | :--- | :--- |
| **인증 및 보안 (Auth)** | Access Token, Refresh Token | OAuth 2.0 상세 흐름 (Scope, Grant Type), 토큰 만료/재발급 로직, 보안 가이드라인. | ★★★★★ |
| **핵심 데이터 (Core Data)** | 잔고, 시세, 거래 내역 | 종목코드(Ticker) 체계, 실시간/지연 데이터 여부, 데이터 필드(Schema)의 정의, 조회 가능한 기간. | ★★★★★ |
| **운영 제약 (Operational)** | Rate Limit, 예외 처리 | 호출 제한 횟수(Rate Limit) 및 초과 시 에러 코드, API별 예외 코드(HTTP Status), 필수 파라미터 누락 시 처리 방법. | ★★★★☆ |

### 📑 2. 필수 조사 항목 체크리스트 (Investigation Checklist)

실제 문서를 탐색할 때 반드시 다음 질문에 대한 답변을 확보해야 합니다.

#### A. 인증 (Authentication)
*   **[필수]** **OAuth 2.0 Flow:** 전체 흐름도(Flowchart)를 확보했는가? (Authorization Code Grant Type 등)
*   **[필수]** **Scope 정의:** 필요한 데이터(예: `accounts:read`, `orders:write`)에 대한 최소 권한 범위(Minimum Scope)를 확정했는가?
*   **[필수]** **Error Handling:** 인증 실패 시의 구체적인 에러 코드와 처리 방안을 알고 있는가?

#### B. 데이터 구조 및 활용 (Schema & Usage)
*   **[필수]** **종목 코드 체계:** 주식, 채권, ETF 등 자산별 고유 식별자(Ticker)의 포맷과 규칙을 파악했는가?
*   **[필수]** **데이터 스키마 (Schema):** 조회 결과 JSON/XML의 모든 필드 이름, 데이터 타입(String, Integer, Float), Null 허용 여부를 정확히 알고 있는가?
*   **[확인]** **데이터 업데이트 주기:** 제공되는 시세 데이터가 실시간(Real-time)인지, 아니면 지연(Delayed) 데이터인지 명확히 했는가? (비즈니스 로직에 치명적)

#### C. 개발 환경 및 제약 (Environment & Constraints)
*   **[필수]** **Rate Limit:** API별로 호출 횟수 제한(Rate Limit)이 얼마이며, 초과 시 재시도 간격(Retry Backoff) 가이드라인이 있는가?
*   **[필수]** **테스트 환경:** Sandbox/Mocking 환경을 제공하는지, 실제 운영 환경과 분리되어 테스트가 가능한가?
*   **[필수]** **문서 버전 관리:** API 문서가 어떤 버전을 기준으로 작성되었는지, 최신 상태를 유지하고 있는지 확인했는가?
